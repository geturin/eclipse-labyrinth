## 固定策略诊断：不是玩家胜率

命令：`npm run balance`。
种子 `BENCH-0`～`BENCH-49`，骑士/法师/巫女，**等级 1、满资源、初始技能与武器**。
每场独立重置，移除游荡小队以隔离战斗规则；没有模拟一路打到 Boss 的升级/领赏。
“战术”只是脚本中的固定启发式：治疗、净化、火冰配合、对预兆用盐/防御。

| 独立场景 | 只普攻 | 固定战术策略 |
| --- | --- | --- |
| B1 普通遭遇 | 34 / 50 胜 | 50 / 50 胜 |
| B1 首领（直接用初始队伍挑战） | 0 / 50 胜 | 19 / 50 胜 |

这些结果说明默认平 A 不再稳定碾压，技能/防护能够改变结果；**不代表真实玩家
的难度概率，更不证明五层通关率、所有职业组合或独行已经平衡**。
后续应根据真实连续跑局记录调整资源、敌阵密度与构筑供给，不只一味增加敌人 HP。

## 未验证/有限验证

浏览器套件使用内存 Storage 替身，因为当前测试环境限制原生本地文件访问。
它能验证应用的序列化/恢复逻辑，**不能证明真实 `file:` localStorage 策略**。
未实测 iPhone Safari、低端手机帧率、音频体验、长时间眩晕改善效果。
即时转向和关闭闪屏是可选舒适措施，不保证所有玩家不再眩晕。

部分浏览器情景（预兆、觉醒、六敌人）由生产引擎构造存档夹具，不代表一次自然
跑局刚好生成了该情景。没有注入线上调试接口，没有发布作弊按钮。
截图由可选浏览器套件在本地生成；原有 PNG 文件的版本说明见 `screenshots/README.md`。

远端 GitHub CI 会独立重新执行 Node 测试和构建；以 Actions 的实际结果为准。
不得把本地报告直接写成“远端 CI 已通过”，也不得把私密仓库写成公开部署。
