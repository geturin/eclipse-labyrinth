# 玩法与工程设计 · v0.1.0

## 设计边界

一名玩家操作 1～3 个不同职业，不是多人联机。保留传统 DRPG 的第一人称格子探索与 JRPG 的指令战斗，不采用战棋格子战场。角色出场时拥有职业的三个主动技能；局内随机提升技能，不实现局外转职树、跨局技能继承或永久数值成长。

目前共有五层，最后一层为最终首领。不存在进入第六层或通关后无限循环。每个格子移动都是离散状态，渲染器用平滑插值表达移动和 90°转身。

## 核心状态机

```text
职业选择 → explore
explore → battle → reward → explore
                 ↘ ended（全队倒下 / 最终首领击破）
explore → reward（宝箱）→ explore
explore → event（休息 / 泉水 / 神像）→ explore 或 reward
explore + 已解锁月门 → 下一层 explore
ended → 职业选择 → 全新 run
```

探索、战斗、奖励和事件弹窗均保存当前局。`ended` 状态不提供继续冒险按钮。暂回标题不清空进度；放弃与覆盖活跃存档需要确认。

## 确定性与地图

种子经哈希后驱动局内伪随机数发生器。迷宫、遭遇、回合随机性、掉落和强化都使用同一个保存的 RNG 状态。因此相同种子还需要**相同编队与操作序列**才能得到相同结果；仅输入相同种子并不能保证不同走法得到同样掉落。

迷宫采用深度优先挖通，再加入环路与连通房间。尺寸为第 1 层 15×15，第 2～3 层 17×17，第 4～5 层 19×19。入口在 (1,1)，月门取从入口 BFS 距离较远的格子；宝箱、休整、神像、精英放在通路上。入口附近另放一个宝箱，在正式消耗战前引入构筑选择。

成功移动增加步数与遭遇压力；撞墙与原地转向不增加压力。每次遭遇之后有短暂无遭遇缓冲。走过的区域永久保留在该层地图；新的一层重新探索。探索不自动掉血，也不实时倒计时。

## 战斗和联携

回合开始按速度排序；加速和减速影响排序及后续轮次。敌人行动自动推进，停在可操作角色时等待输入。没有必须抢按的操作窗口，420ms 的操作锁仅用于动作反馈与防连点。

基础攻击、防御和每职业三个主动技能构成五个主要指令。攻击回复 5 MP；防御回复 7 MP，并在下次行动前减伤 50%。敌人以可见意图描述下一次动作，包含普通攻击、强击、燃烧、毒、守护、蓄力、群攻与吸血。

主要状态：

| 状态 | 规则 |
| --- | --- |
| 破甲 | 受到物理伤害 +35% |
| 星标 | 受到全部攻击伤害 +20% |
| 燃烧 | 行动开始按生命上限的 7% 结算持续伤害 |
| 中毒 | 行动开始按生命上限的 6% 结算持续伤害 |
| 迟缓 | 速度降低，提供冰系武器与忍者联动入口 |
| 迅捷 | 提高速度与造成伤害；时间术士可覆盖全队 |
| 守护 | 降低所受伤害，可与防御叠加 |
| 狂热 | 提高造成伤害；血誓剑士可主动建立 |

冰系命中燃烧目标触发融解 +60%；不同队员连续攻击同一目标叠加联携。忍者根据负面状态增伤，因此自行上毒可单打，与燃烧、破甲、星标、迟缓配合则更强。

单人基础上限补正生命 ×1.45、MP ×1.3，伤害 ×1.25。敌人生命人数系数：单人 0.8、双人 1.12、三人 1.5；敌人数量也有区别。补正并不替代战术或完整平衡测试。

战后小幅回复 MP/生命，倒下的队员会以低生命起身。全队倒下立即结束这一局。普通战可撤退，守门战和最终战不可撤退。技能在修改状态前检查职业归属、MP 和目标有效性。

## 成长与装备

奖励每次三选一。祝福是队伍范围、可叠加的局内效果；有些直接修改最大值或属性，其余在引擎结算时读取层数。技能强化绑定具体角色及其技能，最高 +3。伤害和治疗类通常每级提升基础效能 22%；加速强化增加持续回合，血之契约强化增加 MP 回复，不伪装为伤害提升。

装备只有武器，武器数据由基础数值、品质、类型、一个固定 `effect`、效果说明与实例 `uid` 组成。武器的固有效果固定，而数值随掉落层数成长。没有防具、饰品或随机多词条，所有职业均可装备任意武器。选择武器奖励时必须明确持有者，旧武器放入行囊；战斗期间禁止换装。

神像可消耗 35 星砂，或牺牲全队 20% 生命上限、最低留 1 点，换取一组含传说武器的奖励。宝箱、休整和神像均有消耗状态，不能重复刷同一个已使用事件。

## 代码隔离

`data.js` 是内容定义；`engine.js` 只处理 JSON 可序列化的状态和纯计算，无 DOM 依赖。`app.js` 负责输入、表现和保存；`renderer.js` 读取状态但不裁决战斗。`art.js` 与 `audio.js` 仅生成表现。

光线投射使用 DDA、逐列墙面绘制和 z-buffer 事件遮挡，不依赖 WebGL 库。美术为内嵌 SVG，音乐为 Web Audio 合成。单文件打包器只支持本项目使用的命名导入/导出形式，**不是通用 JavaScript 打包器**；引入外部依赖或复杂模块语法时应更换为合适的构建工具，不能直接扩展正则替换去处理任意程序。

本版本是零依赖 JavaScript ESM，不含 TypeScript 编译工具链。可选浏览器测试使用 Python Playwright，不是游戏运行依赖。

## 修改指引

- 加职业：修改 `JOBS`、`SKILLS`、`makeHero` 所需数据，补充 SVG 配色/装饰、图鉴与职业测试。
- 加武器：在 `WEAPONS` 定义固定效果；在引擎相应的伤害、行动、治疗或死亡钩子中实现，增加确定性测试。
- 加祝福：在 `BOONS` 定义；直接属性增益与动态效果分别进入奖励和战斗结算；明确叠加规则。
- 加敌人：添加数据、行动序列和美术类型，测试速度、持续伤害、群攻和全队死亡的推进。
- 改存档结构：升级 `VERSION` 和 `SAVE_KEY`，设计迁移或明确拒绝旧格式；不要静默把旧存档当成新结构。

任何平衡修改都应同时更新说明和测试，运行 `npm run check` 并手测关键 UI。不要直接编辑生成的 `dist/index.html`；应该修改 `src/` 或 `style.css`，再构建。

## 本版未实现

完整 FFT 式转职/副职业系统、多人联机、云存档、无限模式、任务剧情树、商店经济、专业角色插画、配音、真实移动设备的全面兼容测试与长周期数值平衡。本版提供的是可以继续扩展的完整单局循环，不是这些系统的空入口占位。
